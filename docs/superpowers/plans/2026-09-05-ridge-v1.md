# Ridge v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Ridge v1 as a vault-backed professional trajectory instrument: capture writes chronological markdown events, Core builds disposable projections, Home answers “Where am I going?”

**Architecture:** Headless Core in `src/lib/ridge/` operates on a filesystem vault (source of truth). UI (TanStack Start routes under `/app`) and CLI (`ridge`) are thin callers of the same Core. Indexes live in `.ridge/` and are deterministically rebuildable. No database, queue, auth, or extra service.

**Tech Stack:** TypeScript, Node 22 `node:test`, `yaml` (already installed), `zod`, TanStack Start `createServerFn`, React 19, Tailwind v4. Tests: `node --experimental-strip-types --test`.

**Spec:** `docs/superpowers/specs/2026-09-05-ridge-design.md`

## Global Constraints

- Vault markdown files are the only source of truth. Indexes and views are disposable projections.
- Auth OFF. Do not import `@/lib/db`, `authMiddleware`, or add migrations.
- Do not invent a vault at runtime if it is missing. Ship `data/vault/ridge.yaml` as the starter vault.
- Capture is atomic (temp file + rename). Failed capture leaves no partial event file.
- Capture never overwrites. Filename collisions get `-2`, `-3`, … Stable `id` does not change.
- Event body is frozen byte-for-byte. User-authored headings including `## Notes` are body text. Annotations live only in frontmatter `notes`.
- `interpretation: pending | confirmed` is meaning-state. Pending events are valid evidence on the Timeline.
- Pending events do not appear in a named Evidence Stack until a concept/project name is explicitly confirmed.
- Interpretation is an optional proposal provider. Failure does not affect capture. Proposals are never truth until an explicit user action.
- Destination, next step, and milestone in `ridge.yaml` are user-authored. Projections may read them, never mutate them. Accepting a next step is an explicit Core write of `ridge.yaml`.
- Rename/merge/split updates frontmatter only as an explicit user action. Core never gardens autonomously.
- `events/` is evidence. `reflections/` is never evidence.
- Feature gate: if it does not help build the professional path, it does not enter. No tasks, streaks, hours, XP, skill scores, auto-destination, GitHub-as-truth, skill folders, or capture-requires-commit.
- No comments in code unless a step shows them. No emojis.
- Existing documentation website stays; this plan does not redesign it.
- Every task’s tests use `node --experimental-strip-types --test <file>`.
- Imports use `.ts` extensions (`allowImportingTsExtensions`).

Atomic create:

```ts
async function atomicCreate(destAbs: string, contents: string): Promise<void> {
  if (existsSync(destAbs)) {
    throw new Error(`refusing to overwrite ${destAbs}`);
  }
  const dir = dirname(destAbs);
  await mkdir(dir, { recursive: true });
  const tmp = join(dir, `.${basename(destAbs)}.${process.pid}.${Date.now()}.tmp`);
  try {
    await writeFile(tmp, contents, { encoding: "utf8", flag: "wx" });
    if (existsSync(destAbs)) {
      throw new Error(`refusing to overwrite ${destAbs}`);
    }
    await rename(tmp, destAbs);
  } catch (err) {
    await unlink(tmp).catch(() => {});
    throw err;
  }
}
```

`uniqueEventPath`: loop suffix until `!existsSync`. `id` is not part of the filename.

`openVault`: require `join(root, "ridge.yaml")` exists. Parse with `yaml`. Default empty strings for destination/next_step/milestone. `format` must be `1`.

Corrupt files: parse fails → warning, exclude from events array, do not delete.

- `proposeNextStep`: if `config.destination` is empty, return `null`. Else first confirmed concept that has no `shipped` event, else `null`. This is a suggestion object for UI, not written to yaml.
- `whatChangedView`: window 90 days default; `interpretation` is a short sentence listing kinds that occurred, each backed by ids (e.g. `Built 2, debugged 1.`). If none: `No evidence in this window.` Counts support; do not score hours.
